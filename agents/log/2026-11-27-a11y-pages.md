# Accessibility gate: every workspace page in both themes (T-020)

- Date: 2026-11-27
- Agent: codebuff
- Task: T-020
- Branch: `agent/a11y-pages`

## Goal
The gate only audited the generated workspace's landing page, so Board, Calendar and Analytics —
which render different catalog components — were never scanned. Walk all four project-template
pages in light and dark and fix what axe finds.

## Changed
- `e2e/accessibility.spec.ts` — `PROJECT_PAGES` lists Overview, Board, Calendar and Analytics,
  each with a marker component; `openPage` clicks the real sidebar entry and waits for the page
  heading plus that component. The workspace test now audits all four pages light, switches theme
  once, then audits all four dark.
- `components/workspace/render/task-views.tsx` — the calendar grid gained six `role="row"`
  wrappers (`display: contents`, layout unchanged) so its `columnheader`/`gridcell` roles have a
  valid parent; the per-cell `aria-label` that omitted visible task titles was removed, and the
  now-unused `formatDateLong` import went with it.
- `app/globals.css` — outside-month cells no longer fade the whole cell (`opacity: 0.4` dropped
  their labels below 4.5:1); they use a transparent surface and a faint day number. Calendar chips
  mix 30% black into the accent in the light palette (4.2:1 before), keeping the accent in dark.
  New `--s-danger` token (`#b91c1c` light, `#fca5a5` dark).
- `components/workspace/render/insight-views.tsx`, `input-views.tsx`, `task-views.tsx` —
  `text-red-500` (3.8:1 on light) replaced with `text-[var(--s-danger)]`.
- `ARCHITECTURE.md` — ADR-15 records the multi-page coverage and each Calendar/Analytics fix.
- `IMPLEMENTATION_PLAN.md`, `README.md` — the axe item and the `test:e2e` row say every workspace
  page is scanned in both themes.
- `agents/tasks.md` — T-020 moved to `review`; T-019 was marked `done` separately in #17.
