# Accessibility gate: the interface surface is scanned in both themes (T-019)

- Date: 2026-11-27
- Agent: codebuff
- Task: T-019
- Branch: `agent/a11y-dark`

## Goal
Close ADR-13's coverage gap: the axe gate only ever saw the light interface palette, so the dark
tokens, priority pills and primary-button text had never been audited.

## Changed
- `e2e/accessibility.spec.ts` — a `switchTheme` helper drives the real Appearance → Theme control,
  asserts `data-theme` and `aria-pressed`, closes the menu, then audits
  `generated workspace (dark)` after the light pass. The header records that the chrome is
  single-palette, so the dashboard and account page already are the dark shell.
- `components/workspace/render/task-views.tsx` — the task-count badge lost its `aria-label`.
  Axe reports `aria-prohibited-attr` (serious) on a role-less `span`; the badge sits beside the
  card title, so the label added nothing and could be ignored by AT.
- `ARCHITECTURE.md` — ADR-14 records the extension, why only the surface has two palettes, and the
  two remaining ungated incompletes.
- `IMPLEMENTATION_PLAN.md`, `README.md` — the axe item and the `test:e2e` row say both interface
  themes are scanned.
- `agents/tasks.md` — T-012 closed (`done`, merged as #15); T-019 filed, claimed and moved to
  `review`; `agents/log/README.md` indexes this entry.
