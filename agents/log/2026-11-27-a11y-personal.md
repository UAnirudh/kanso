# Accessibility gate: the personal template's pages (T-023)

- Date: 2026-11-27
- Agent: codebuff
- Task: T-023
- Branch: `agent/a11y-personal`

## Goal
The axe gate generated only the project template, so the personal tracker's Today, Calendar and
Progress pages — a different catalog set — were never scanned in either palette. Generate that
template too and gate its pages.

## Changed
- `e2e/accessibility.spec.ts` — `PERSONAL_PAGES` lists Today (`StatSummary`), Calendar (`Calendar`)
  and Progress (`ProgressChart`); a shared `generateWorkspace` helper creates either template,
  asserts the fresh document starts light, and the new test audits the three personal pages light,
  switches through the Appearance control, then audits them dark.
- `ARCHITECTURE.md` — ADR-16 records the coverage; ADR-15 stays as written (append-only ADRs).
- `IMPLEMENTATION_PLAN.md`, `README.md` — the axe item and the `test:e2e` row say both templates'
  pages are scanned in both themes.
- `agents/tasks.md` — T-023 added at `review` with this entry.

## Verified
- `npx playwright test e2e/accessibility.spec.ts` → 3 passed (38.4 s): the dashboard/account
  test, eight project-template audits and six personal-template audits (three pages × two
  themes); no serious or critical violations.
- `npm run typecheck` → exit 0.
- `npm run test:e2e` → 7 passed (1.2 m), including the new personal-template test at 9.4 s
- CI on this branch → not run when this entry was written; the PR checks gate it

## Not verified

- Accent, density and navigation variants: same scanned components, not audited separately.
